## Accessorial model

- **Line grain:** `(tenant_id, accessorial_id, currency_code)` with pinned `mapping_version` / `mapping_evaluated_at` from `cost_summary_projection` attribution pin
- **Period grain:** `(tenant_id, buyer_company_id, normalized_category, period_start, MONTH, currency_code)`
- **Eligible lines:** `status = APPROVED` only in default projection; period from parent order fact (`cost_summary_projection.updated_at` month, same as v2.2B/C)
- **Category resolution:** tenant override → platform → `OTHER`; unmapped charge codes counted in coverage

## Period metrics

| Metric | Definition |
|--------|------------|
| `total_amount` | SUM approved eligible accessorial amounts in slice |
| `order_count` | DISTINCT orders with ≥1 eligible line in category slice |
| `line_count` | COUNT eligible lines |
| `share_of_spend` | category `total_amount` ÷ SUM `current_actual_amount` from order facts (same tenant/buyer/period/currency) |
| `accessorial_order_rate` | distinct orders with accessorial ÷ eligible orders in period scope |
| `freight_spend_total` | SUM `current_actual_amount` denominator used for share |

## Enrichment snapshots

Batch-hydrated during tenant rebuild and incremental dirty processing:

- `order_reference` ← transport order `order_number`
- `carrier_display_name` ← company `short_name` preferred over `legal_name`
- `lane_label` ← canonical `BuildLaneLabel(origin, dest, mode, equipment)` (display only; identity remains `lane_key`)

Workspace detail reads snapshots from `cost_analytics_order_fact` before UUID fallbacks.

## Update model

Same dirty-queue pattern as v2.2B/C:

1. Rebuild: delete accessorial facts/projections → hydrate enrichment → rebuild facts from billing batch → reaggregate period slices
2. Incremental: capture previous accessorial facts → rebuild order accessorial lines → reaggregate old **and new** category/period slices

## Non-goals (v2.2D)

- Public analytics API (v2.2F)
- Benchmark / opportunity rules using accessorial rate (v2.2E)
- N+1 HTTP in projection build (batch APIs required when clients configured)
