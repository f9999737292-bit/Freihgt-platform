**Status:** Implemented

## Scope

v2.2C adds tenant/company/currency-safe **lane** and **carrier** period projections on top of v2.2B `cost_analytics_order_fact`.

`V2_2C_SEQUENCE_AMENDMENT=YES` — minimal internal batch dimension API added in transport-order-service (dimension fields only). v2.2D batch-summary with display enrichment remains deferred.

## Lane model

- **Grain:** `(tenant_id, buyer_company_id, lane_key, transport_mode, equipment_type, period_start, MONTH, currency_code)`
- **Key format:** `{CC}:{CITY}->{CC}:{CITY}|{MODE}|{EQUIPMENT|WILD}`
- **Directional:** YES
- **Missing city/country/mode:** excluded from lane cohort; counted in coverage

## Carrier model

- **Grain:** `(tenant_id, buyer_company_id, carrier_company_id, period_start, MONTH, currency_code)`
- **Identity:** `carrier_company_id` UUID only (no display name)
- **Missing carrier:** excluded from carrier cohort

## Metrics (CLASS A, no benchmark)

Lane: `order_count`, `carrier_count`, planned/accrued/current/final totals, variance totals  
Carrier: `order_count`, `lane_count`, same financial totals

## Update model

Same as v2.2B: dirty queue on ingest + tenant rebuild. Incremental reaggregates **old and new** lane/carrier/period slices on dimension or cost changes.

## Non-goals (v2.2C)

- Median / P25 / P75 / benchmark / savings (v2.2E)
- Accessorial intelligence (v2.2D)
- Display enrichment / order_reference / carrier_display_name (v2.2D)
- Public analytics API / workspace UI (v2.2F)
- Class C KPIs (distance, cost/km, pallet, LDM, budget, forecast)
