# FREIGHT COST INTELLIGENCE v2.2E — Tenant Benchmarking & Explainable Savings Opportunities

**Status:** Implemented  
**Date:** 2026-08-23  
**Prerequisite:** v2.2D merged (PR #56 @ `e47740ee`)

---

## 1. Scope

v2.2E converts existing tenant/company/currency-safe v2.2B–D projections into:

- **Tenant-only lane cost benchmarks** (count, mean, median, P25, P75, P90, min, max)
- **Lane-normalized carrier comparison signals**
- **Rule-based explainable savings opportunities** with deterministic identity and evidence

### In scope

- Benchmark domain model and dedicated projection tables
- Configurable minimum benchmark sample (default 5)
- `INSUFFICIENT_SAMPLE` semantics — no percentile values when below threshold
- Opportunity projection with observed / baseline / estimated_delta
- Full tenant rebuild and incremental affected-cohort recompute
- Internal S2S validation reads only
- Observability (low-cardinality Prometheus counters)

### Out of scope (v2.2F+)

- Public `/api/v1/freight-costs/analytics/*` or `/opportunities`
- Gateway analytics routes and workspace intelligence UI
- Cross-tenant / market benchmarks
- ML, FX, forecast, distance, cost/km, budget, pallet/LDM
- CLASSIFICATION_ANOMALY opportunity (no valid monetary baseline without fabrication)
- CRM / workflow lifecycle on opportunities

## 2. Benchmark contract

| Decision | Value |
|----------|-------|
| **Scope** | Tenant-only (`CROSS_TENANT_BENCHMARK=NO`) |
| **Company scope** | `tenant_id` + `buyer_company_id` — companies never mixed |
| **Sample unit** | One eligible transport order per observation |
| **Cost basis** | Per-order finality: `FINAL_ACTUAL` or `CURRENT_ACTUAL` — never mixed in one distribution |
| **Open costs** | DRAFT/accrual rows excluded (`lane_eligible` + non-null eligible amount) |
| **Cohort grain** | `tenant_id`, `buyer_company_id`, `lane_key`, `transport_mode`, `equipment_type`, `period_start`, `period_grain`, `currency_code` |
| **Period window** | Explicit projection period cohorts from order facts (month grain) — no undocumented rolling window |
| **Currency** | Mandatory grain; no FX; no cross-currency distributions |
| **Percentile method** | PostgreSQL `percentile_cont` in SQL (authoritative) |
| **Rounding** | Full NUMERIC precision in SQL; round to money scale (2 dp) at projection boundary |
| **Min sample config** | `FREIGHT_COST_ANALYTICS_MIN_BENCHMARK_SAMPLE` (default 5) |
| **Carrier normalization** | Lane-normalized delta vs lane cohort median; no raw global carrier average |
| **Carrier self-inclusion** | Full tenant lane median includes all carriers on the lane |

## 3. Database

Migration `000064_freight_cost_benchmark_savings_v2.2E`:

| Table | Purpose |
|-------|---------|
| `freight_cost.cost_analytics_benchmark_projection` | Stored lane cohort statistics |
| `freight_cost.cost_analytics_opportunity_projection` | Rule-based savings opportunities |

Primary keys enforce tenant isolation. Opportunity `estimated_delta >= 0` constraint prevents negative “savings”.

---

## 4. Opportunity types

| Type | Implemented | Formula / rule |
|------|-------------|----------------|
| `LANE_COST_OUTLIER` | YES | Order cost > lane cohort P90 (sample ≥ min) |
| `COST_ABOVE_LANE_MEDIAN` | YES | Order cost > lane cohort median |
| `CARRIER_COST_OUTLIER` | YES | Lane-normalized: carrier median positive delta vs lane median across comparable orders |
| `HIGH_ACCESSORIAL_RATE` | YES | Order accessorial rate > tenant P75 for same buyer/period/currency |
| `REPEATED_VARIANCE` | YES | Same carrier/lane + pinned variance driver ≥ configurable min occurrences (default 3) |
| `CLASSIFICATION_ANOMALY` | NO | Deferred — no defensible monetary baseline without fabrication |

Every money opportunity includes: `observed_amount`, `baseline_amount`, `estimated_delta`, `currency_code`, `sample_size`, `rule_version`, versioned `evidence_json`.

Opportunity ID: deterministic SHA1 UUID from tenant, company, type, scope, entity key, currency, period, rule version.

---

## 5. Rebuild & incremental

Pipeline order during tenant rebuild:

```text
v2.2B order/period facts
  → v2.2C lane/carrier
  → v2.2D accessorial/enrichment
  → v2.2E benchmarks
  → v2.2E opportunities
```

Incremental: affected lane cohort keys trigger full cohort percentile recompute (not additive approximation). Stale opportunities for affected lanes/periods are pruned.

## 6. Internal validation API

S2S only (no gateway wiring):

- `GET /internal/v1/freight-cost/analytics/tenants/{tenantId}/benchmarks`
- `GET /internal/v1/freight-cost/analytics/tenants/{tenantId}/opportunities`

Filters: buyer company, currency, lane, period, opportunity type. Bounded pagination.

## 7. Security

- Tenant A data never affects Tenant B benchmarks (FC22E-SEC-001)
- Buyer company X never affects company Y within same tenant (FC22E-SEC-002)
- RUB and EUR produce separate cohorts (FC22E-CUR-001)
- Carrier must not receive buyer benchmark data (future public API gated in v2.2F/G)
