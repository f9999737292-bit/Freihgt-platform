## Source of truth

```
ANALYTICS_PROJECTION_AUTHORITATIVE=NO
CANONICAL_SOURCE=cost_summary_projection (active per transport order)
ACTIVE_FACTS_ONLY=YES
SUPERSEDED_ROWS_INCLUDED=NO (ledger not summed; summary is active state)
```

Analytics rebuild reads **`cost_summary_projection` only**, not raw `cost_entry` sums.

## Projection grain

### Order fact

`(tenant_id, transport_order_id, currency_code)`

### Period projection (base v2.2B deliverable)

`(tenant_id, buyer_company_id, period_start, period_grain=MONTH, currency_code)`

### Period date source

`ANALYTICS_PERIOD_DATE_SOURCE=cost_summary_projection.updated_at` (calendar month UTC)

## Metrics (CLASS A only)

- `order_count` — distinct transport orders
- `planned_total`, `accrued_total`, `current_actual_total`, `final_actual_total`
- `current_variance_total`, `final_variance_total`
- `reconciliation_open_count` — open/reopened findings linked to orders in period

## Update model

| Path | Mechanism |
|------|-----------|
| Incremental | Transactional dirty queue on ingest apply (`analytics_projection_dirty`) |
| Full rebuild | `RebuildTenant` — delete tenant rows + rebuild from summaries |
| Scheduled | Worker ticker (`FREIGHT_COST_ANALYTICS_REBUILD_INTERVAL`, default 24h) |

Worker default **disabled**: `FREIGHT_COST_ANALYTICS_PROJECTION_ENABLED=false`

## Atomicity

Tenant rebuild runs in a single DB transaction with `pg_advisory_xact_lock` per tenant.

## Idempotency

- Dirty upsert on `(tenant_id, transport_order_id, currency_code)`
- Repeated tenant rebuild produces identical business metrics
- Duplicate ingest events do not duplicate dirty rows beyond upsert refresh
