## 1. Overview

v2.2F exposes buyer-facing Freight Cost Intelligence built on v2.2B–E projections:

```text
Browser (JWT) → API Gateway (RBAC + company membership) → freight-cost-service
  /api/v1/freight-costs/analytics/*  →  /internal/v1/freight-costs/analytics/*
  /api/v1/freight-costs/opportunities → /internal/v1/freight-costs/opportunities
```

No analytics calculations in the browser. Frontend is presentation, filters, and navigation only.

## 3. RBAC & Security

- **JWT required** at gateway; browser never sends S2S token.
- Gateway strips untrusted identity headers (`X-Tenant-ID`, `X-User-ID`, `X-Role`, `X-Platform-Admin`).
- **X-Company-ID** membership validated before forward.
- **PolicyBuyerAnalytics** on all five routes — carrier actors receive **403**.
- Tenant scope: JWT tenant must match trusted resolved tenant; spoofed tenant headers ignored.
- Company scope: data limited to `tenant_id + buyer_company_id` from verified membership.
- Internal S2S paths under `/internal/v1/freight-cost/analytics/tenants/*` are **not** exposed via gateway.

## 4. DTO Semantics

### Money

Amounts serialized as decimal strings (`"45000.00"`), never JSON floats. Unavailable amounts are `null`/omitted — never `"0.00"` unless actual zero.

### Cost basis / finality

Public overview preserves separate fields:

- `current_actual_total`
- `final_actual_total`
- `financial_finality`
- `data_stage`

`CURRENT_ACTUAL` is never labeled as final.

### Benchmark basis

`benchmark_cost_basis`: `FINAL_ACTUAL_OR_CURRENT_ACTUAL_PER_ORDER` — eligible per-order finality only; open costs excluded from benchmark cohorts.

### Data quality

| Value | Meaning |
|-------|---------|
| `AVAILABLE` | Projection data present |
| `PARTIAL` | Some sections missing |
| `NOT_AVAILABLE` | Capability/projection unavailable — not zero |
| `INSUFFICIENT_SAMPLE` | Benchmark omitted when sample < min |
| `STALE` | Stale projection returned with freshness metadata |
| `MIXED_CURRENCY` | No cross-currency total; per-currency breakdown |

### Freshness

Responses include `calculated_at`, `data_through`, `projection_version` where applicable.

## 5. Filters & Pagination

- **Date range:** default rolling 90 days; max ~24 months; server validates `from <= to`.
- **Currency:** exact ISO filter when provided; mixed currencies → `MIXED_CURRENCY` without combined total.
- **Pagination:** default 20, max 100; `total`, `limit`, `offset` on list endpoints.
- **Sort allowlists** per `ANALYTICS_CONTRACT.md`; unknown sort → 400.

## 7. Frontend Architecture

**App:** `apps/web-procurement`

- **Feature flag:** `NUXT_PUBLIC_FREIGHT_COST_WORKSPACE_ENABLED` — default **OFF** (`!== 'true'`).
- **Route:** existing `/freight-costs/*` workspace extended with Intelligence tabs.
- **Composable:** `useFreightCostAnalyticsApi.ts`
- **Utils:** `freightCostIntelligence.ts`
- **Components:** `components/freight-cost/intelligence/*`
- **Tabs:** Overview, Lanes, Carriers, Accessorials, Opportunities
- **i18n:** RU / EN / ZH in `i18n/*/freightCosts.json`

Frontend does **not** compute benchmarks, medians, or opportunity rules. Uses backend `estimated_delta` only.
