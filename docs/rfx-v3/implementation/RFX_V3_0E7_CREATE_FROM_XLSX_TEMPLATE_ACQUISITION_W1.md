## Workbook

Generator: `xlsxexchange.GenerateBuyerCreateBlankWorkbook()`.

It reuses `buyerSheetOrder`, `lotsHeaders` / `sectionsHeaders` / `questionsHeaders` / `optionsHeaders` / `rulesHeaders`, and the shared text cell writer. It does **not** call `GenerateBuyerDraftWorkbook` with an empty snapshot.

Sheets: Instructions, Metadata, Lots, Sections, Questions, Options, Rules.
Metadata keys: `schema_name=BINTRANS_RFX_BUYER_XLSX_V1`, `schema_version=1` only.
Tabular sheets are header-only. Instructions describe CREATE upload, not auto-publish or participant creation.

Parser lock: generated bytes are passed to `ParseBuyerCreatePreview` (same path as `POST /xlsx-create/preview`). Expected: `CREATE_NEW_DRAFT`, schema/version parity, ready-to-commit empty optional graph, no identity warnings, no formulas.

## Controller notes (non-blocking)

These notes do not change the product contract and are not W2/W3 scope:

- Gateway registration after `GET /{id}` is safe because Chi matches by segment count (`xlsx-create/template` is not captured as `{id}`).
- Extra OpenAPI `400`/`409` on this GET are cosmetic inheritance from the shared Excel error block.
- Flag-off `404` remains the existing Excel-exchange `http.NotFound` text/plain pattern.
- `BinaryAttachment` interpolates filename unsanitized; this endpoint uses the constant `bintrans-rfx-buyer-xlsx-v1-create-template.xlsx`, so header injection is not available on this path.
